# bishOS Life OS — build spec (2026-10-20)

Source research: `reports/Founder life operating system.md` (read its tables if you need the "why").
Scope: Phases 1–4 of that report. **The company layer (Phase 5: multi-user, seats, permissions,
Accountability Chart) is out of scope.** It will be a separate platform. Keep `owner` fields as
"me" where present.

## Who it's for

Bish: a startup co-founder with almost no team. He handles delivery/operations, sales and
marketing himself, learns constantly, and wants to build a personal brand plus company content.
His current Life Areas:

1. **Company Operations** (delivery, clients, admin)
2. **Company Sales & Marketing** (pipeline, offers, campaigns, outreach)
3. **Personal Learning & Content** (learning areas, personal brand and company content)
4. **Fitness** (coming soon)

He said: *"If it's attractive, I'll be there. If it's addictive, I'll be there. Otherwise it won't
work for me."* Every screen must be **useful first, beautiful second, and fast**. Rewards are
positive only: XP, levels, confetti and forgiving streaks. No guilt walls of red overdue items.

## Design principles (from the research)

- **One owner per layer:** Areas are the spine → annual goals (≤8) → 12-week goals (≤3 active,
  key results = lag, tactics = lead) → projects (one area, ≤1 goal) → tasks ("when" ≠ deadline)
  → week plan (Weekly Big 3) → day (Top 3 placed into maker/manager blocks).
- **Weekly review is the product.** Everything feeds it or is changed by it. It must be pre-filled
  and resumable, with a 20-minute minimum mode.
- **Defend against abandonment:** caps (≤3 goals, ≤5 active projects, 1–3 new habits), capacity
  check, bulk reschedule, "fresh start" after absence, no silent rollover (keep / schedule / drop),
  reserve skips and streak repair, consistency % before streak counts, full export.
- **AI removes maintenance; it never acts silently.** Show a preview, and the user confirms each
  change.
- **Evidence over numerology:** 85% / Big 3 / 3 goals are editable defaults, not laws.

## Conventions (MUST follow)

### Backend (Convex)
- Every function starts with `const userId = await requireUser(ctx)` (from `./helpers`). Check
  `doc.userId === userId` before reading or changing a doc by id.
- Tables live in `convex/schema.ts`; the Life OS block is at the bottom. Fields are documented
  inline. **Don't rename or remove existing fields or literals.** If you truly need a new field,
  add it as `v.optional(...)` inside a table your module owns. Re-read the file right before the
  Edit, because other builders edit the same file.
- **Dates:** every Life OS `date` is a client-LOCAL `YYYY-MM-DD` string sent by the client. Every
  `weekStart` is the local **Monday**. Server-side date math lives in `convex/os.ts`: `addDays`,
  `diffDays`, `weekday`, `mondayOf`, `daysBetween`, `monthKey`. Never use `new Date()` on the
  server to decide "today" when the client can pass `date`/`today` args.
- **XP:** `awardXp(ctx, userId, key, amount, reason, date)` and `revokeXp(ctx, userId, key)` in
  `convex/os.ts`, with amounts in `XP` there. Use stable keys (`deal-won-<id>`,
  `recall-<cardId>-<date>`…) so toggling can't farm XP, and revoke when an action is undone.
- **Settings:** `getSettings(ctx, userId)` (`convex/os.ts`) returns defaults merged with the
  `userSettings` doc (caps, quotas, capacity, income, currency…).
- **AI:** `callOpenRouter(messages)` from `./openrouter` inside `action`s only. Parse defensively.
  Never write from an AI action without the user confirming in the UI. Return proposals, and let
  the client call normal mutations to apply them.
- After adding a new convex file run `npx convex codegen --typecheck disable`, then
  `npx tsc --noEmit`. Fix errors in your files only. Never run `npx convex dev` or `deploy`.

### Frontend (Next.js app router, client components)
- Pages live in `app/(app)/<route>/page.tsx` and start with `"use client"`.
- Use **`PageShell`** from `components/os/kit.tsx` for every page (Topbar + container + header).
  Use `Section` for cards, `Chip`, `Ring`, `Bar`, `Metric`, `Segmented`, `Field`, `TextInput`,
  `TextArea`, `Select`, `InlineEdit`, `ListEditor`, `Drawer`, `Dialog`, `EmptyHint`, `Kanban`,
  `ItemCard`, `CheckCircle`, `Avatar`, `areaColor`, `AreaDot`, and the re-exported
  `buttonVariants` / `badgeVariants` / `inputClass` / `cn`.
- Celebrate wins: `import { toast, reward, celebrate } from "@/components/os/celebrate"`.
  `reward("Deal won 🎉", 100, true)` shows a toast with an XP pill and confetti.
- Local dates: `lib/day.ts` (`useToday()`, `todayYmd`, `addDaysYmd`, `mondayOf`, `weekDays`,
  `fmtYmd`, `relDay`, `fmtMin`, `clockLabel`, `greeting`). Pass `date`/`today` to mutations.
- **Design system (Syncora): don't change it.** Primary is black/white, and colour is reserved
  for meaning: `success|warning|danger|info` (+ `-soft` backgrounds), `chart-1..5` for categories,
  `sprint` (violet) for challenges and sprints. Cards: `rounded-xl border border-border bg-card
  shadow-card`. Popovers: `bg-popover shadow-raised`. **Never hardcode white/black or Tailwind
  palette colours** (no `bg-green-500`). Everything must work in light AND dark.
- Motion classes in globals.css: `os-pop`, `os-rise`, `fade-in`, `os-shine`. Keep motion subtle.
- Responsive: usable at 360px wide. Grids collapse to one column; boards scroll horizontally.
- Loading: when `useQuery` returns `undefined`, render skeletons (`<div className="skeleton h-24" />`)
  rather than empty states.
- Empty states always say what the thing is for and offer a primary action (`EmptyHint`).
- Keyboard: Ctrl/⌘+K command palette and `C` quick-capture are global (built by the core). Don't
  bind single-letter shortcuts globally in module pages.
- The existing primitives in `components/ui.tsx` (Card, Modal, StatCard, Topbar…) are still fine
  to use.

## Module specs

### CORE (owner: lead) — Phase 1 daily loop
- `convex/inbox.ts`: capture, list, triage (task / note / commitment / idea / person / discard /
  snooze), and an "older than 48h" flag.
- `convex/days.ts`: Day page, start-up and shutdown rituals, check-in (sleep h, sleep quality
  1–5, energy 1–5, mood 1–5), Top 3, if-then plan, capacity, resume note, progress line, lesson,
  journal, day type, and the ritual streak with weekly reserve shields. It also mirrors the
  check-in into `dailyCheckIns` so existing analytics keep working.
- `convex/today.ts`: the Today cockpit aggregate (reads all tables).
- `convex/game.ts`: XP, levels and streaks. `convex/settings.ts`: settings. `convex/exportData.ts`:
  full JSON export.
- UI: `/today`, `/inbox`, `/journal` (+ `/journal/[date]`), `/settings`, the start-up and shutdown
  ritual flows, the command palette, quick capture, Toaster, Sidebar and onboarding.

### A · Direction (compass, goals, week, reviews) — Phase 2
- `convex/compass.ts`: get/update the compass doc. Area standards and weekly hour targets
  (patch `lifeAreas.standard` / `weeklyHoursTarget`). Area ratings (`areaRatings`) with history.
- `convex/cycles.ts`: create, list and get the active 12-week cycle. Cycle week number. Close a
  cycle (grade goals). Suggest the next start (next Monday).
- Goals: extend `convex/goals.ts` **additively**. Keep every existing export working; other pages
  use `goals.list/get/create/update/addMilestone/...`. Add:
  - `level`, `cycleId`, `parentGoalId`, `goalType`, `goalStatus`, `reasons`, `keyResults`
    (lag), `woop` and `grade`.
  - Enforce the active 12-week goal cap with `getSettings().maxActiveGoals`: block the change and
    return a clear error the UI shows.
- `convex/tactics.ts`: tactics CRUD; `logTactic({tacticId, weekStart, delta})`; the weekly
  execution score = Σ min(done, target) / Σ target over the active cycle goals' tactics. **Also
  count habits that have `goalId`** (completions that week vs `weeklyTarget ?? 7`, skips excluded).
  Return per-week history for the cycle (12 points).
- `convex/weekPlans.ts`: get/upsert the week plan (Weekly Big 3, free day, notes), set Big 3
  done, and hours by area for the week (planned blocks vs focus sessions vs
  `lifeAreas.weeklyHoursTarget`).
- `convex/idealWeek.ts`: get/save the template (day types + blocks) and
  `applyToWeek({weekStart})`, which creates `scheduleBlocks` with `blockType` and
  `fromTemplate: true`. It skips blocks that would overlap existing blocks and never duplicates.
- `convex/periodicReviews.ts`: get-or-create a draft per (kind, periodKey); save one step's
  answers; complete. Completing awards XP: weekly 120, monthly 150, quarterly 300, annual 500.
  Pre-fill queries:
  - **weekly:** wins (completed tasks, progress lines), Big 3, execution score, habit
    consistency, inbox count, projects with no next action, tasks untouched 30+ days, deals with
    no next step (stage not won/lost/unqualified and no `nextStepDate`), idle deals (lastTouch
    > 7d), open commitments by direction, scorecard numbers, open issues, someday items.
  - **monthly:** area ratings, goal status, habits to graduate/shrink/drop, hours by area vs
    target, stale tasks.
  - **quarterly:** grade KRs (0–1), average execution, successes/mistakes, burnout check (3
    questions), next goals (≤3) with tactics + WOOP, prune.
  - **annual:** past-year review (top peaks), went well/badly lists, ~80% healthy, theme,
    Free Days first.
  - AI: `periodicReviews.aiDraft(kind, periodKey)` drafts a summary from the pre-fill data.
- UI:
  - `/compass`: purpose, values, vision (overall + per area), not-to-do, year theme, and a Wheel
    of Life radar (SVG) with this month's ratings and history.
  - `/goals`: the 12-week cockpit. Cycle header ("Week 4 of 12" + progress), ≤3 active goal cards
    (KR progress, tactics checklist for THIS week with +/− counters, execution trend sparkline),
    this week's execution score ring, the annual goals backlog, the someday backlog, and a "start
    a new cycle" wizard. Keep existing goals visible; legacy goals without `level` show in an
    "Other goals" list with a "convert to 12-week goal" action.
  - `/goals/[id]`: the existing detail page enhanced with reasons, KRs, tactics, WOOP coach
    (AI-assisted, interactive), linked projects/tasks/habits, and milestones (existing).
  - `/week`: week plan. Weekly Big 3, a 7-day strip (day type, theme, planned vs done, Top 3 per
    day from `days`), tactics for this week, hours by area (target vs planned vs actual), a
    protected Free Day picker, an Ideal Week editor (visual weekly grid of template blocks,
    maker/manager colour coding via tokens), and "Apply Ideal Week to this/next week".
  - `/reviews`: a hub with cards for the current weekly/monthly/quarterly/annual review (status,
    last done), history, and a step-by-step wizard per kind (`/reviews/[kind]`, `?period=`).
    Resumable, with a minimum-mode toggle, pre-filled data and celebration on completion.
    `app/(app)/review/page.tsx` must become a redirect to `/reviews`. The old weekly review UI
    can be deleted. Keep `convex/reviews.ts`, because the dashboard and AI may use it.

### B1 · Sales & relationships — Phase 3
- `convex/people.ts`: people + companies CRUD; `interactions.log` (updates `lastContactAt` and the
  deal's `lastTouchAt`); due-to-reconnect list (cadenceDays elapsed since lastContactAt); search.
- `convex/deals.ts`:
  - **Stages:** Target → Contacted → Conversation booked → Discovery done (pain, budget and
    decision-maker confirmed) → Proposal sent → Verbal yes → Won / Lost / Unqualified.
  - **Next step:** an open deal can't be saved without `nextStep` + `nextStepDate`. Reject in the
    mutation and require it in the UI.
  - **Flags:** idle (no touch for 7+ days), stuck (14+ days in a stage), proposal open (9+ days).
  - **On win:** optionally create a delivery project (Company Operations area by default) linked
    via `dealId`/`companyId`, set the company to `customer`, and award `XP.dealWon`.
  - **On lost/unqualified:** keep the person as a nurture contact (set `cadenceDays` 90 if unset).
  - **Daily outreach:** count = interactions of kind outreach/followup today vs
    `settings.outreachQuota`. "Open to goal" mode: when the meetings booked today ≥
    `settings.meetingsGoal`, the block is done.
  - **Metrics:** win rate, pipeline value by stage, velocity.
- `convex/commitments.ts`: CRUD, set status, promise-keeping rate (kept on time ÷ due) for the
  last 4 weeks, due today/overdue, and "waiting for" check dates. Awards `XP.commitmentKept`
  when an "I owe" commitment is kept on time.
- `convex/aiRouting.ts`: `routeConversation({text})` takes pasted call/meeting notes or a
  transcript. It returns proposals: commitments (direction, person, date), deal updates or new
  deals, people, content ideas (objections and questions), and tasks. The UI shows checkboxes and
  applies them through normal mutations.
- UI:
  - `/pipeline`: Kanban by stage, with value totals per column. Deal cards show the next step +
    date (overdue = warning chip), flags and the person. Drag to move; moving to an open stage
    asks for the next step. Header: today's outreach quota meter (log a touch in one click),
    win rate and pipeline value. A list view toggle. Deal drawer: qualification, interactions
    timeline, commitments, notes, offer/campaign, and won/lost actions.
  - `/people`: CRM table + "Due to reconnect" rail, with filters by relation/tier and a
    companies tab. `/people/[id]`: profile, timeline, deals, commitments, cadence, notes, and
    "log touch".
  - `/customers`: companies with relationship=customer, their delivery projects, open
    commitments, health (green/yellow/red), last contact and revenue (won deal values).
  - `/commitments`: two columns ("I owe" / "Owed to me"), due today/overdue/upcoming, quick add
    with a person picker, promise-keeping rate ring, and a "route a conversation" (AI) button.

  repair) already exists and is used by Today, so keep its signature.
  - Add update args for `anchor`, `minVersion`, `stretchVersion`, `weeklyTarget`, `reserveSkips`,

    - Production = high $ + energizing
    - Investment = low $ + energizing
    - Replacement = high $ + draining
    - Delegation = low $ + draining
    (high $ = value ≥ 3).
  - **Buyback Rate** = annualIncome ÷ 2000 ÷ 4 (from settings), with hours you could buy back.
  - Process library (SOPs) CRUD: 7–15 steps suggested, rung admin/delivery/marketing/sales/

  - Monthly 3-question burnout pulse stored in `periodicReviews` answers (monthly) or its own
